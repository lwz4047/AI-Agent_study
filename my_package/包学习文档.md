# Python 包（Package）学习文档

> 本文档基于 `my_package/` 目录下的 `__init__.py`、`calc.py`、`greet.py`、`py_package.py` 整理而成。

---

## 一、什么是包？

**包（Package）** 是一个包含 `__init__.py` 文件的**目录**。  
它是对多个模块的集合与组织，用于管理更大规模的代码结构。

```
my_package/              ← 这就是一个包（目录）
├── __init__.py          ← 必须存在，标识这是一个包
├── calc.py              ← 子模块：计算功能
├── greet.py             ← 子模块：问候功能
└── py_package.py        ← 演示如何使用包
```

> **模块 vs 包：**  
> - 模块 = 一个 `.py` 文件  
> - 包 = 一个含有 `__init__.py` 的目录（可包含多个模块）

---

## 二、包的结构解析

### `calc.py` —— 计算模块

```python
# calc.py

def add(x, y):
    return x + y
```

提供加法功能，接收两个参数，返回它们的和。

---

### `greet.py` —— 问候模块

```python
# greet.py

def say_hi(name):
    print(f"Hello,{name}! ")
```

提供问候功能，接收姓名参数，打印欢迎语。

---

### `__init__.py` —— 包的初始化文件

```python
# __init__.py

__all__ = ["calc", "greet"]
```

**`__init__.py` 的两大作用：**

1. **标识身份：** 告诉 Python "这个目录是一个包"，没有它目录就只是普通文件夹
2. **初始化配置：** 包被导入时，`__init__.py` 中的代码会被自动执行

---

## 三、`__all__` 详解

`__all__` 是一个字符串列表，专门控制 `from 包名 import *` 的导入范围。

### 在包的 `__init__.py` 中

```python
__all__ = ["calc", "greet"]
```

含义：当外部执行 `from my_package import *` 时，**只导入 `calc` 和 `greet` 两个模块**，其他模块不会被导入。

### 在普通模块中

```python
# 假设某模块 utils.py
__all__ = ["add", "subtract"]  # 只对外暴露这两个函数

def add(a, b): ...
def subtract(a, b): ...
def _private_func(): ...  # 下划线开头，本就不会被 * 导入
```

### `__all__` 与 `import *` 的关系

| 情况 | `from 模块 import *` 的行为 |
|------|---------------------------|
| 定义了 `__all__` | 只导入 `__all__` 列表中的名称 |
| 没有定义 `__all__` | 导入所有不以 `_` 开头的名称 |

> **注意：** `__all__` 只影响 `import *`，不影响精确导入（如 `from my_package import calc`）。

## 四、导入包的四种方式

### 方式一：`import 包名.模块名`（精准导入）

```python
import my_package.calc

# 使用方式：包名.模块名.功能
result = my_package.calc.add(8, 2)
print(result)  # 10
```

**特点：** 路径最完整，命名空间最清晰，**不会产生任何歧义**。

---

### 方式二：`from 包名 import 模块名`（简化导入）

```python
from my_package import greet

# 使用方式：模块名.功能（不需要写包名前缀）
greet.say_hi("小王")  # Hello,小王!
```

**特点：** 省略了包名前缀，书写更简洁，**日常开发最常用**。

---

### 方式三：`from 包名 import *`（批量导入）

```python
from my_package import *  # 根据 __all__ = ["calc","greet"] 导入

# 可以直接使用 calc 和 greet 模块
print(calc.add(1, 2))   # 3
greet.say_hi("小李")    # Hello,小李!
```

**特点：** 一次导入所有在 `__all__` 中声明的模块，方便但可能污染命名空间。

---

### 方式四：`from 包名.模块名 import 功能名`（最深层导入）

```python
from my_package.calc import add

# 直接使用函数名，无需任何前缀
print(add(1, 2))  # 3
```

**特点：** 导入最精准，只引入需要的那一个函数/类，**推荐在大型项目中使用**。

---

## 五、四种导入方式对比

| 导入方式 | 使用语法 | 命名空间污染 | 适用场景 |
|----------|----------|------------|----------|
| `import 包.模块` | `包.模块.功能()` | 无 | 需要明确来源时 |
| `from 包 import 模块` | `模块.功能()` | 较少 | 日常开发，最常用 |
| `from 包 import *` | `模块.功能()` | 中等 | 快速脚本，慎用 |
| `from 包.模块 import 功能` | `功能()` | 较多 | 只需单个函数时 |

## 六、完整使用示例

```python
# ============ 示例 1：精准导入 ============
import my_package.calc

print(my_package.calc.add(10, 5))   # 15

# ============ 示例 2：from 包 import 模块 ============
from my_package import greet, calc

greet.say_hi("Alice")    # Hello,Alice!
print(calc.add(3, 7))    # 10

# ============ 示例 3：批量导入（依赖 __all__）============
from my_package import *

print(calc.add(100, 200))   # 300
greet.say_hi("Bob")         # Hello,Bob!

# ============ 示例 4：最深层导入 ============
from my_package.calc import add
from my_package.greet import say_hi

print(add(6, 4))     # 10
say_hi("Charlie")    # Hello,Charlie!
```

## 七、`__init__.py` 的进阶用法

`__init__.py` 不仅用于标识包，还可以在其中做初始化配置，让使用者更方便地调用：

```python
# __init__.py（进阶写法示例）

# 将子模块的功能直接暴露到包层级
from .calc import add
from .greet import say_hi

__all__ = ["add", "say_hi"]
```

这样配置后，使用者可以直接从包名导入函数，而不需要知道它来自哪个子模块：

```python
from my_package import add, say_hi

print(add(1, 2))   # 3
say_hi("张三")      # Hello,张三!
```

> **注意：** `.calc` 中的点号 `.` 表示**相对导入**，代表当前包内的模块，
> 区别于绝对导入 `my_package.calc`。

## 八、包的嵌套（子包）

包可以继续嵌套，形成多层目录结构：

```
my_project/
├── __init__.py
├── utils/
│   ├── __init__.py
│   ├── math_utils.py
│   └── string_utils.py
└── models/
    ├── __init__.py
    └── user.py
```

导入方式：

```python
from my_project.utils import math_utils
from my_project.models.user import User
```

## 九、知识点汇总

| 知识点 | 说明 |
|--------|------|
| 包 | 含有 `__init__.py` 的目录 |
| `__init__.py` | 包的标识文件，包被导入时自动执行 |
| `__all__` | 控制 `import *` 时对外暴露的名称列表 |
| `import 包.模块` | 精准导入，命名空间最清晰 |
| `from 包 import 模块` | 最常用的导入方式 |
| `from 包 import *` | 批量导入，受 `__all__` 控制 |
| `from 包.模块 import 功能` | 最精准的导入，只引入单个功能 |
| 相对导入 `from .模块 import` | 在包内部模块间互相引用时使用 |

## 十、补充：包与模块的关系图

```
Python 代码组织层级（从小到大）：

  语句 / 表达式
       ↓
    函数 / 类
       ↓
    模块（.py 文件）
       ↓
    包（含 __init__.py 的目录）
       ↓
    项目（多个包的集合）
```

> **最佳实践：**
> - 相关功能放在同一个模块中
> - 相关模块放在同一个包中
> - `__init__.py` 保持简洁，不要写复杂逻辑
> - 优先使用 `from 包名 import 模块名` 或 `from 包名.模块名 import 功能名`
> - 避免在生产代码中使用 `import *`

## 十一、绝对导入 vs 相对导入

Python 包内部模块之间互相引用时，有两种导入方式：

### 绝对导入（推荐）

从项目根目录开始写完整路径，清晰明确：

```python
# 在 my_package/calc.py 中引用同包内的 greet 模块
from my_package.greet import say_hi   # 绝对导入

say_hi("绝对导入示例")  # Hello,绝对导入示例!
```

### 相对导入

用 `.` 表示当前包，`..` 表示上级包，只能在包内使用：

```python
# 在 my_package/calc.py 中
from .greet import say_hi      # . 代表当前包（my_package）
# from ..other import func    # .. 代表上一级包

say_hi("相对导入示例")  # Hello,相对导入示例!
```

### 两种方式对比

| 对比项 | 绝对导入 | 相对导入 |
|--------|----------|----------|
| 语法 | `from my_package.greet import say_hi` | `from .greet import say_hi` |
| 可读性 | 高，路径一目了然 | 低，依赖当前所在位置 |
| 包重命名 | 需要修改所有导入路径 | 无需修改 |
| 适用场景 | 日常开发，**推荐** | 包内部模块互相引用时 |
| 能否直接运行 | 可以 | 不能直接运行该文件（需作为包的一部分运行） |

> **注意：** 相对导入只能在包内使用，直接运行含有相对导入的文件会报：  
> `ImportError: attempted relative import with no known parent package`

## 十二、`__init__.py` 中的包元信息

规范的包通常在 `__init__.py` 中声明版本号、作者等元信息，方便其他开发者了解包的基本情况：

```python
# __init__.py

# 包的元信息
__version__ = "1.0.0"
__author__  = "小明"
__email__   = "xiaoming@example.com"
__doc__     = "这是一个包含计算和问候功能的示例包。"

# 控制 import * 的范围
__all__ = ["calc", "greet"]
```

外部使用时可以直接读取这些元信息：

```python
import my_package

print(my_package.__version__)  # 1.0.0
print(my_package.__author__)   # 小明
print(my_package.__doc__)      # 这是一个包含计算和问候功能的示例包。
```

## 十三、循环导入问题

**循环导入** 是包开发中常见的错误：模块 A 导入模块 B，而模块 B 又导入模块 A，形成死循环。

### 问题示例

```python
# a.py
from b import func_b   # a 导入 b

def func_a():
    print("func_a")

# b.py
from a import func_a   # b 又导入 a → 循环！报 ImportError

def func_b():
    print("func_b")
```

运行时会报错：`ImportError: cannot import name 'func_a' from partially initialized module 'a'`

### 解决方法：提取公共部分到第三个模块

```python
# common.py（新建，存放公共功能）
def shared_func():
    print("shared")

# a.py
from common import shared_func  # 改为从 common 导入，不再导入 b

# b.py
from common import shared_func  # 同上
```

> **原则：** 如果两个模块互相依赖，说明它们之间有公共逻辑，应该提取成第三个模块。

## 十四、命名空间包（Python 3.3+）

Python 3.3 之后，目录即使**没有 `__init__.py`** 也可以作为**命名空间包**被导入。

```
tools/              ← 没有 __init__.py
├── formatter.py
└── validator.py
```

```python
# 仍然可以导入（命名空间包）
from tools import formatter
```

### 普通包 vs 命名空间包

| 对比项 | 普通包 | 命名空间包 |
|--------|--------|----------|
| `__init__.py` | 必须有 | 不需要 |
| 初始化代码 | 可以在 `__init__.py` 中写 | 不支持 |
| 跨目录合并 | 不支持 | 支持（同名包可分布在不同路径） |
| 适用场景 | 日常项目开发 | 大型框架、插件系统 |

> **建议：** 日常学习和项目开发中，仍然保留 `__init__.py`，更加明确和规范。

## 十五、常见错误与解决

| 错误类型 | 原因 | 解决方法 |
|----------|------|----------|
| `ModuleNotFoundError: No module named 'my_package'` | 包的父目录不在 `sys.path` 中 | 在项目根目录运行脚本，或添加路径到 `sys.path` |
| `ImportError: cannot import name 'xxx'` | `__all__` 中未包含该名称，或名称拼写错误 | 检查 `__all__` 列表和名称拼写 |
| `ImportError: attempted relative import` | 含相对导入的文件被直接运行 | 改为绝对导入，或作为包的一部分运行 |
| `AttributeError: module has no attribute` | 导入了包但未导入具体模块 | 明确导入子模块，如 `from my_package import calc` |
| 循环导入 `ImportError` | 模块间存在循环依赖 | 提取公共逻辑到第三个模块 |
